# systemd-boot Snapper

Add recent Snapper root snapshots to the systemd-boot menu. Labels use the snapshot's date, time, type, and stored description. The generator discovers compatible Linux entries already on disk. It prefers a matching non-LTS kernel and falls back to LTS when available. Snapshot entries reuse the existing kernel and initramfs files on the EFI partition.

**Made with OpenAI Codex and checked by a human.** On CachyOS, the maintainer booted an equivalent recovery entry into Plasma with Secure Boot enabled and verified that creating and deleting a Snapper snapshot automatically added and removed its menu entry. Distribution-independent entry discovery was checked with local fixtures.

## Requirements

- systemd-boot on x86, with the FAT EFI System Partition mounted at `/boot`.
- A Btrfs root subvolume named `@` and a Snapper `root` configuration with snapshots stored under `/.snapshots` on that root filesystem.
- A Boot Loader Specification Type #1 Linux entry with a separate kernel and initramfs, a filesystem UUID in `root=`, `rw`, and `rootflags=subvol=/@` or `rootflags=subvol=@`. The generator skips UKIs and entries for an EAC kernel.
- Python 3, `file`, `btrfs-progs`, and the systemd-based mkinitcpio setup with the `sd-volatile` hook for each kernel used by snapshot entries.

## Set up root snapshots

Check your existing configuration first.

```sh
sudo snapper list-configs
sudo snapper -c root list
```

If you have no Snapper configuration for `/` and `/.snapshots` does not exist, create a `root` configuration with `sudo snapper -c root create-config /`. This starts a fresh root snapshot history alongside any existing configurations, such as one for `/home`.

Snapper creates the snapshots and controls retention. The generator reads them from disk and updates the boot menu. Use `sudo snapper -c root get-config` to check `TIMELINE_CREATE`, the cleanup settings, and the retention limits. Check `snapper-timeline.timer` and `snapper-cleanup.timer` with `systemctl status`. On pacman-based distributions, `snap-pac` can be installed separately to take pre/post snapshots around package transactions.

**On CachyOS**, `cachyos-snapper-support` is optional for this project. Its removal script runs `snapper -c root delete-config`, which deletes the root configuration **and its snapshots**, and disables the system-wide cleanup timer. Removing the package can also remove `snap-pac` if it was installed as a dependency. Check your timer and package state after removal.

## Install

Run these commands from the repository checkout in a Bash-compatible shell. The preview reads the installed kernel versions and Snapper metadata and prints the entries it would create.

```sh
sudo python3 ./systemd-boot-snapper
```

If `sd-volatile` is absent from your initramfs, add the hook and rebuild the presets for the kernels you want to boot with snapshots. These example preset names are for Arch Linux. Use the preset names installed on your system.

```sh
printf '%s\n' 'HOOKS+=(sd-volatile)' |
  sudo tee /etc/mkinitcpio.conf.d/90-snapshot-boot.conf
sudo mkinitcpio -p linux
sudo mkinitcpio -p linux-lts
```

Install the generator and event hooks.

```sh
sudo install -Dm755 systemd-boot-snapper /usr/local/sbin/systemd-boot-snapper
sudo install -Dm644 systemd-boot-snapper.service /etc/systemd/system/systemd-boot-snapper.service
sudo install -Dm644 systemd-boot-snapper.path /etc/systemd/system/systemd-boot-snapper.path
sudo install -Dm755 90-systemd-boot-snapper /usr/lib/snapper/plugins/90-systemd-boot-snapper
sudo systemctl daemon-reload
sudo systemctl enable --now systemd-boot-snapper.path
sudo systemd-boot-snapper --apply
sudo bootctl --no-pager list
```

On pacman-based distributions, install the optional post-transaction hook.

```sh
sudo install -Dm644 zzz-systemd-boot-snapper.hook /etc/pacman.d/hooks/zzz-systemd-boot-snapper.hook
```

## Update an existing installation

From an updated checkout, replace the generator and the Snapper event plugin, then refresh the menu.

```sh
sudo install -m755 systemd-boot-snapper /usr/local/sbin/systemd-boot-snapper &&
  sudo install -m755 90-systemd-boot-snapper /usr/lib/snapper/plugins/90-systemd-boot-snapper &&
  sudo systemd-boot-snapper --apply
```

## Refresh and boot

Snapper events refresh the menu when a root snapshot is created, changed, or deleted, and when the root configuration is created or deleted. The optional pacman hook refreshes it after kernel updates and the snap-pac post-snapshot. On other package managers, refresh manually after upgrading a kernel. The generator keeps up to six compatible read-only snapshots and removes its stale entries. It writes files only when the contents change.

If `/.snapshots` is absent, a preview reports zero compatible snapshots. An applied refresh removes only entries marked as generated by this project. An older generator may report a `findmnt -T /.snapshots` error in this situation. Update the installed generator and plugin using the commands above.

To refresh manually, run `sudo systemd-boot-snapper --apply`. At startup, select a snapshot by its date and description. The generated `a-snapper-auto-*.conf` IDs sort snapshots below typical regular Linux entries, newest snapshot first.

To check the automatic refresh, create a root snapshot and look for its description with `sudo bootctl --no-pager list`.

```sh
sudo snapper -c root create --description "Initial root snapshot" --cleanup-algorithm number --print-number
```

If the entry is missing, run `sudo systemd-boot-snapper` to preview compatible snapshots and check `journalctl -u systemd-boot-snapper.service` for refresh errors.

## Recovery behavior

- The snapshot root gets a writable overlay in RAM. Changes to that overlay disappear on reboot. Writes to separate live mounts, such as `/home` or `/data`, persist.
- An older snapshot can disappear from the menu when a kernel update leaves it without matching modules for either installed kernel. Snapper retains the underlying snapshot according to its own cleanup rules.
- On the tested CachyOS configuration, `systemd-remount-fs.service` reported a failure because it tried to apply the Btrfs root options from `fstab` to OverlayFS. Plasma still started with the overlay mounted.

## Uninstall

```sh
sudo systemctl disable --now systemd-boot-snapper.path
sudo systemctl stop systemd-boot-snapper.service
sudo rm -f /etc/pacman.d/hooks/zzz-systemd-boot-snapper.hook \
  /usr/lib/snapper/plugins/90-systemd-boot-snapper \
  /etc/systemd/system/systemd-boot-snapper.service \
  /etc/systemd/system/systemd-boot-snapper.path \
  /usr/local/sbin/systemd-boot-snapper
sudo systemctl daemon-reload

# Remove only entries marked as generated by this project.
sudo find /boot/loader/entries -maxdepth 1 -type f \( \
  -name 'a-snapper-auto-*.conf' -o -name 'snapper-auto-*.conf' \) \
  -exec grep -qxF '# Generated by systemd-boot-snapper' {} \; -delete
```

If you added `90-snapshot-boot.conf` for this project, you can remove that drop-in and rebuild the regular and LTS initramfs images.
